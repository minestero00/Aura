## Features

1. **버스 도착 알림 — client-driven 전환**
   - 서버 trip 상태(transit_trips DB) 의존 제거. trip은 device AsyncStorage에만 저장.
   - 정류장 도착은 OS Region Monitoring(iOS) / GeofencingClient(Android)이 감지 → 앱이 꺼져 있어도 native가 깨어나서 알림 표시.
   - 알림 메시지에 stop 이름 포함 (`옥수역 근처에 도착했습니다`).

2. **목적지 검색 결과 — 네이버 지도 스타일 timeline**
   - 헤더: `34분 · 도보 8분 · 환승 1회 · 15.4km`
   - 노선 색 동그라미(서울/수도권 표준 — 1~9호선/신분당/분당/공항/경의중앙 등) + departure → arrival stop + headsign + 정거장 수.
   - 4자리 버스 번호도 동적 fontSize로 원 안에 들어가게.

3. **도보 자동 진행 + 최종 도착 알림**
   - 도보 leg는 다음 transit 정류장을 target으로 잡아 자동 advance — 사용자가 "다음 단계로" 누를 필요 X.
   - 마지막 leg 도착 시 별도 메시지: `{목적지}에 거의 도착했어요. 조심히 도착하셨나요?`

4. **권한 deep link 일원화**
   - 위치/알림/캘린더 등 "차단됨" status row를 직접 누르면 권한 흐름 시작. 거부 상태면 OS 설정으로 즉시 deep link.
   - Android 11+ background location은 in-app prompt가 막혀있어 무조건 Settings 경로 — 자동으로 처리.
   - 권한 부여 후 foreground 복귀 시 `backgroundActive` 자동 retry — banner의 "위치 권한 설정 열기" 버튼이 자동으로 사라짐.

5. **화면 상단 AURA 작은 아이콘**
   - 5탭 모든 hero eyebrow 옆에 흰색 tint 16x16 AURA 마크. 어디 있든 우리 앱 안이라는 일관된 시각 신호.

## 인프라 / 운영

### Cache 수정 — reload 시 quota counter 누적 차단

기존: `/api/v1/briefings/daily-brief`와 `/api/v1/gmail/daily-summary`가 라우트 단계에서 `consumeOrThrow`를 무조건 호출 → cache hit이어도 quota counter +1. Cmd+R 한 번에 카운터가 한 칸씩 올라가던 사용자 보고.

수정: `consumeOrThrow`를 service 안 cache miss 분기로 이동. cache hit 응답에서는 LLM 호출도, counter 증가도 없음. 분당 rate limit은 cache hit fast-path에서 우회되지만 cache hit은 비용 거의 0이므로 무관.

### Step 7 — backend transit_trips legacy 코드 제거

client-driven 전환으로 server-side trip lifecycle endpoint들이 모두 dead code가 됨. 614줄 삭제:

- `POST /transit/trips`, `GET /trips/active`, `GET /trips/recent`, `POST /trips/:id/ping`, `POST /trips/:id/end` 라우트
- `service.ts` (startTrip/getActiveTrip/listRecent/ping/endTrip 메서드)
- `transit-api.ts` (Google Maps 래퍼는 `directions.ts`로 대체)
- 관련 type/schema 정리

DB 테이블 `aura.transit_trips`는 그대로 유지 — 데이터 손실 차단. 추후 별도 마이그레이션으로 DROP 검토.

### Android 첫 빌드 통과

iOS는 이미 빌드 OK였고, Android는 first-time이라 세 가지 잠재 이슈 동시 해소:

- **Kakao SDK maven repo 누락** — `react-native-seoul/kakao-login`의 `com.kakao.sdk:v2-*`가 maven central에 없음. `settings.gradle`에 `https://devrepo.kakao.com/nexus/...` 추가.
- **namespace ↔ Kotlin package 불일치** — `namespace "com.dumbteam.aura"`인데 Kotlin 파일들은 `package com.auraapp`. R class를 못 찾음. 모든 Kotlin 파일을 `com.dumbteam.aura.*`로 통일.
- **hermesc binary 경로** — RN 0.84의 default(`node_modules/react-native/sdks/hermesc/%OS-BIN%/hermesc`)에 binary 없음. 별도 패키지(`node_modules/hermes-compiler/hermesc/...`)로 `hermesCommand` 명시.

`./gradlew :app:assembleRelease` BUILD SUCCESSFUL → `app-release.apk` 67MB.

## Native module

### iOS — `front/ios/TransitGeofence.swift` (Swift)

`RCTEventEmitter` 서브클래스 + `CLLocationManagerDelegate`. JS에서 `startMonitoring(regions)` 부르면 `CLLocationManager.startMonitoring(for: CLCircularRegion)`. ENTER 이벤트는 OS가 background/suspended 상태에서도 깨워서 전달 — `didEnterRegion`에서 `UNUserNotificationCenter`로 알림 즉시 표시 + JS event emit + 같은 region 자체 stop(재발사 방지). region별 stop 이름/타입은 `UserDefaults`에 영구 저장 → 앱 완전 종료 상태에서 OS가 깨워도 알림 메시지에 정류장 이름 포함.

### Android — `front/android/app/src/main/java/com/dumbteam/aura/transit/` (Kotlin)

세 파일: `TransitGeofenceModule.kt`(RN bridge) + `GeofenceBroadcastReceiver.kt`(BR) + `TransitGeofencePackage.kt`(ReactPackage). Google Play Services `GeofencingClient`. ENTER는 `BroadcastReceiver.onReceive`로 들어오고 `NotificationCompat`으로 알림 + JS event emit. metadata는 `SharedPreferences`. iOS와 같은 정책으로 한 번 ENTER 후 `removeGeofences`.

### 알림 권한 흐름

- iOS: native가 `requestAlwaysAuthorization` 호출. 한 번 거부됐으면 in-app으로 다시 못 묻고 Settings deep link만.
- Android: `PermissionsAndroid.request(ACCESS_FINE_LOCATION)` → API 29+에서 `ACCESS_BACKGROUND_LOCATION` 추가 request. **Android 11+(API 30+)는 background 권한 in-app prompt 자체가 막혀있어** 즉시 `settings-needed` 반환 → `Linking.openSettings()`로 OS 앱 상세 페이지로 이동.

### 권한 변경 후 자동 retry

`useGeofenceTracker`에 `AppState change` listener 추가 — `state="active"`로 돌아왔을 때 `backgroundActive=false`였다면 `startBackgroundMonitoring(regions)` 재호출. 사용자가 OS Settings에서 "Always" 선택 후 앱 복귀 → banner hint가 자동으로 "앱이 꺼져 있어도 도착 시 알림을 보내드려요."로 갱신.
